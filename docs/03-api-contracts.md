# 03 — API contracts

`packages/contracts` is the source of truth. Change the OpenAPI spec, regenerate clients, then
implement. Never invent a request shape at a call site.

```
packages/contracts/
├─ openapi/
│  ├─ gateway.yaml        # everything the four clients call
│  ├─ ai.yaml             # gateway → ai service
│  ├─ docai.yaml          # gateway → docai service
│  └─ terminology.yaml    # gateway → terminology service
├─ events.ts              # WebSocket event names + payload types (shared)
└─ generated/             # committed, regenerated by `pnpm gen`
```

Conventions: REST over HTTP for request/response, WebSocket for anything the server initiates.
`snake_case` in JSON. ISO 8601 UTC timestamps. Every error is
`{ error: { code, message, details? } }` with a machine-readable `code`.

## Gateway — session lifecycle

```http
POST   /v1/sessions                     → { session_id, resume_token, qr_url }
GET    /v1/sessions/:id                 → full session state + progress
POST   /v1/sessions/:id/resume          { resume_token } → rebinds a new device
POST   /v1/sessions/:id/language        { language: "hi" }
POST   /v1/sessions/:id/consent         { scopes[], audio_uri? }
POST   /v1/sessions/:id/answer          { slot_id, value, input_mode, confidence?, audio_uri? }
                                        → { next_question, progress, red_flags[] }
POST   /v1/sessions/:id/complete        → { summary_id }
DELETE /v1/sessions/:id                 → purge (patient-initiated withdrawal)
```

`POST /answer` is the hot path. It must return the next question in the same response — a
second round trip blows the 1.2 s budget.

## Gateway — identity

```http
POST /v1/identity/abha/qr               { qr_payload } → { patient_id, demographics }
POST /v1/identity/abha/otp/request      { abha_number | mobile } → { txn_id }
POST /v1/identity/abha/otp/verify       { txn_id, otp } → { patient_id, token }
POST /v1/identity/register              { name, age, sex, phone? } → { patient_id }
```

`ABDM_MODE=mock` serves all four from the mock gateway with identical shapes. Nothing above
changes when real credentials arrive — only the adapter behind it.

## Gateway — documents

```http

GET  /v1/documents/:id                  → { status, extractions[], quality_score }
GET  /v1/sessions/:id/timeline          → chronologically ordered clinical events
```

## Gateway — clinician

```http
GET   /v1/visits/queue?department=      → prioritised token queue
GET   /v1/visits/:id/summary            → structured summary + provenance
PATCH /v1/visits/:id/summary            { field_path, value } → physician edit
POST  /v1/visits/:id/sign               → { fhir_bundle_id, abdm_status }
POST  /v1/visits/:id/ask                { question } → grounded answer + cited field ids
GET   /v1/visits/:id/diff               → follow-up delta vs previous visit
```

## WebSocket events

Rooms: `session:{id}` and `department:{code}`.

| Event | Direction | Payload |
|---|---|---|
| `audio.chunk` | client → server | binary, 16 kHz PCM |
| `transcript.partial` | server → client | `{ text, is_final }` |
| `slot.filled` | server → client | `{ slot_id, value, confidence }` |
| `question.next` | server → client | `{ question, tts_url, input_modes[], options[] }` |
| `redflag.fired` | server → both rooms | `{ rule_id, severity, quote, token_no }` |
| `queue.updated` | server → department | `{ tokens[] }` |
| `document.processed` | server → session | `{ document_id, extractions[] }` |
| `session.resumed` | server → session | `{ device_id }` |

## Internal — ai service

```http
POST /transcribe        { audio_ref, language, streaming } → { text, confidence, segments[] }
POST /fill-slot         { slot_schema, utterance, context } → { value, confidence, needs_clarification }
POST /next-question     { module_id, state, language } → { text, tts_url, options[] }
POST /evaluate-flags    { module_id, slots }          → { fired[] }     # deterministic, no model
POST /summarise         { answers[], extractions[] }  → { structured, rendered_en, rendered_local }
POST /synthesise        { text, language }            → { audio_url }   # cached
```

`/evaluate-flags` must have no model call in its implementation. If it ever gains one, that is
a bug against CLAUDE.md rule 3.

## Internal — docai service

```http
POST /classify   { image_ref } → { doc_type, confidence }
POST /process    { document_id, image_refs[] } → 202 Accepted, result via WS
GET  /jobs/:id   → { status, result? }
```

## Internal — terminology service

```http
GET  /search?q=amavata&system=namaste   → ranked concepts (trigram + vector)
GET  /concept/:system/:code             → concept detail + synonyms
POST /translate                         { system, code, target } → ConceptMap match
GET  /fhir/CodeSystem/:id
GET  /fhir/ConceptMap/:id/$translate?code=&system=&target=
```

## Rules

1. **Additive changes only, once Day 1 ships.** Add a field, do not rename one. Six people
   cannot chase a breaking change on day four.
2. **Every endpoint returns something useful on partial failure.** A summary with three
   missing fields is worth more than a 500.
3. **`session_id` on every log line** across every service. It is how anything gets debugged.
4. **Idempotency key on `POST /answer`.** Flaky hospital wifi means retries; a duplicated
   answer must not advance the interview twice.

# @careflow/contracts

Source of truth for every interface between a client and the gateway, and between the gateway
and a service. See `docs/03-api-contracts.md`.

```
openapi/
  gateway.yaml        everything the four clients call
  ai.yaml              gateway → ai service
  docai.yaml           gateway → docai service
  terminology.yaml     gateway → terminology service
events.ts              WebSocket event names + payload types (shared)
generated/             committed, regenerated by `pnpm gen`
  ts/                  one openapi-typescript output per spec
  python/              one openapi-python-client output per spec
```

## Workflow

Change a spec under `openapi/`, then regenerate:

```
pnpm gen          # both TS and Python
pnpm gen:ts       # openapi-typescript only
pnpm gen:python   # openapi-python-client only (self-contained venv under .venv/)
```

Never invent a request shape at a call site — if the shape you need isn't in a spec here, add
it to the spec first.

## Rules (docs/03-api-contracts.md)

1. Additive changes only, once Day 1 ships. Add a field, do not rename one.
2. Every endpoint returns something useful on partial failure.
3. `session_id` on every log line, across every service.
4. Idempotency key on `POST /answer` — retries on flaky hospital wifi must not advance the
   interview twice.

Conventions: REST over HTTP for request/response, WebSocket for anything the server initiates.
`snake_case` in JSON. ISO 8601 UTC timestamps. Every error is
`{ error: { code, message, details? } }` with a machine-readable `code`.

## Python client generation

`pnpm gen:python` creates its own venv at `packages/contracts/.venv` (gitignored) rather than
joining the `services/*` venv loop in the root `Makefile`, since this package isn't a service.
It installs the pinned `openapi-python-client` version from `requirements.txt` and regenerates
`generated/python/{gateway,ai,docai,terminology}_client`.
